# v8.6.1 — 저장 증거 AI 실행 수정

[유스케이스](USE_CASES.md) · [검증 기록](V861_VERIFICATION.json) · [남은 단계](REMAINING_STEPS.md)

## 수정한 문제

기존 환경에서는 ChatGPT 로그인과 모델 목록 조회가 성공해도 `codex exec`가 첫 실행 이벤트 전에 멈췄습니다. 같은 설정에서 120초를 기다려도 이벤트가 없었고, CLI 0.158.0·0.159.2·0.162.1에서 재현됐습니다. 분석용 자식 프로세스의 프로젝트 문서 탐색을 `project_doc_max_bytes=0`으로 제한하자 세션이 즉시 시작됐습니다. 탐색 내부의 정확한 저수준 정지 원인은 확인하지 않았습니다.

분석용 자식 프로세스는 별도 임시 폴더에서 명시적인 분석 프롬프트와 마스킹한 저장 증거를 입력받습니다. 관련 없는 프로젝트 문서를 읽지 않으며, 호출하는 개발·검토 에이전트의 저장소 지침은 그대로 적용됩니다. ChatGPT 인증 파일, 사용자 설정 파일, 관리 정책과 읽기 전용 샌드박스는 변경하지 않습니다.

그다음 CLI가 보내는 비치명적 경고인 `item.type=error`를 도구 실행으로 오인하던 검사를 수정했습니다. 경고는 모델 응답으로 계산하지 않습니다. 최종 답변과 `turn.completed`, JSON 스키마, 저장 증거 인용 검사가 모두 있어야 성공입니다. 실제 도구 실행과 최상위 오류·실패 이벤트는 계속 거부합니다.

실제 리뷰 스키마의 `uniqueItems`는 모델 서비스가 엄격한 구조화 출력에서 거부했습니다(`invalid_json_schema`, HTTP 400). 전송용 복사본에서만 이 키워드를 제외하고, 저장된 스키마와 수신 결과의 중복 ID·인용 검사는 유지합니다. 같은 오류는 원문 응답을 노출하지 않는 `OUTPUT_SCHEMA_UNSUPPORTED` 코드로 구분합니다. [공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했습니다.

모델 도구 이벤트 외부에서 실행될 수 있는 사용자 훅·알림 명령·셸 스냅숏을 분석 프로세스에서 끄고, 번들 스킬 설치도 막습니다. 기능 플래그는 설치된 CLI가 지원하는 것만 적용합니다. 다른 Codex 세션의 설정을 수정하거나 스킬·인증 파일을 교체하지 않습니다.

## 사용법

기존에 ChatGPT로 로그인한 Codex CLI가 `PATH`에 있어야 합니다.

```bash
python ai_review.py doctor --probe --timeout 90 --first-response-timeout 45 --output reports/ai-doctor
python ai_review.py batch-run --batch reports/ai-batch --timeout 300 --first-response-timeout 90
python ai_review.py batch-report --batch reports/ai-batch --output reports/ai-review
```

실패 원인을 수정한 뒤에만 `--retry-failed`로 실패 패킷을 재시도합니다. 이미 완료한 패킷은 건너뜁니다. 새 진단·보고서 출력에는 사용하지 않은 디렉터리를 지정하세요.

실제 모델 probe는 CLI 0.162.1과 기존 로그인으로 정상 완료했습니다. 배치 검토의 완료 수·인용·커버리지·평가는 [검증 기록](V861_VERIFICATION.json)에 별도로 기록합니다. 저장 증거 분석은 대상에 새 요청을 보내지 않으며, AI 의견만으로 실제 취약점 재현이나 사람의 최종 확정을 대신하지 않습니다.
