# AI 모델 설정과 대량 저장 자료 처리 — 2026-10-16

사용자 지정에 따라 프로젝트의 AI 검토 기본 모델을 **GPT-6.1 Sol (`gpt-6.1-sol`) / `medium`**으로 설정했습니다. `doctor --probe`, `codex`, `batch-run`, `recommend --ai`의 공통 자식 프로세스가 `--model gpt-6.1-sol -c 'model_reasoning_effort="medium"'`을 명시합니다. 기존 `--model` 옵션으로 모델만 바꿀 수 있으며 추론 강도는 medium을 유지합니다. 전역 Codex 설정은 변경하지 않습니다.

실행 기록·진단·추천 JSON에 `requested_model`, `requested_reasoning_effort`를 남깁니다. 요청 설정의 기록이며 서버 내부 모델 snapshot의 독립 확인은 아닙니다. 모델·강도를 캐시 지문에 연결하고 캐시 버전을 변경해 이전 모델 미지정 결과를 새 설정의 결과로 재사용하지 않습니다. 따라서 첫 AI 실행에서는 이전 캐시를 통한 절약이 없을 수 있습니다. 과거 batch 완료 결과는 역사적 결과로 보존되므로 새 설정으로 다시 검토하려면 새 batch를 준비합니다.

공식 문서: [모델과 CLI 선택](https://learn.chatgpt.com/docs/models), [설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol). 모델 접근 가능 여부는 로그인 계정·CLI·배포 상태에 따라 다릅니다. 접근 실패를 다른 모델의 성공으로 대체하지 않습니다. 이번 변경에서 실제 모델 서비스 호출과 기존 77건의 추가 AI 검토는 수행하지 않았습니다.

## 5,000건이면 오래 걸리는가?

**전부 AI로 검토하면 오래 걸릴 수 있습니다.** 요청·응답 기록 수, 규칙 후보 수, CLI 검토 묶음 수, CLI 내부 모델 요청 수는 서로 다릅니다. 현재 `summary.model_calls`는 실행기에 제출한 CLI 검토 묶음 수이며 공급자 내부 요청 수나 실제 청구 토큰 수를 측정하지 않습니다.

| 단계 | 현재 동작 |
|---|---|
| 로컬 처리 | 범위 안의 저장 자료 전체를 규칙과 관련 증거 구성에 사용합니다. 본문 크기·후보 수·비교 관계가 많으면 시간과 메모리가 증가합니다. |
| 기본 AI 추천 | 새 검토 예산 최대 24단위. 규칙 후보 1개 또는 탐색 묶음 1개가 각각 1단위입니다. |
| 규칙 후보 전달 | 최대 8개씩, 입력 크기 24KiB 이하로 나누고 동시 실행 2개입니다. 크기 제한 때문에 24후보가 반드시 3호출이 되는 것은 아닙니다. |
| 규칙 밖 탐색 | `--discover` 선택 시 기본 최대 4묶음이 같은 24단위 예산을 공유합니다. 한 묶음 최대 3개 관련 기록, 대표 탐색 풀 최대 200묶음으로 전체 자료 검토를 보장하지 않습니다. |
| 반복 실행 | 같은 캐시 파일과 새 출력 폴더를 사용하면 유효한 과거 결과는 재사용하고 다음 미검토 후보를 선택합니다. 기본 캐시 유효기간 24시간·최대 2,000항목이며 만료·설정·증거 변경 시 새 검토가 필요합니다. |
| 전체 증거 batch | 별도 `batch-run`은 준비된 모든 묶음을 순차 처리합니다. 추천 경로의 24단위·동시 2개와 혼동하지 마세요. |

예를 들어 작은 후보 24개가 8개씩 들어가면 CLI 검토는 3묶음입니다. 반면 후보 5,000개를 모두 검토한다는 가정에서는 최소 625묶음이며, 묶음당 30초·동시 2개라면 대략 2시간 37분입니다. **실제 측정이 아닌 산술 예시**이고 입력 크기 분할·네트워크 지연·사용량 제한·실패·사전 처리가 추가될 수 있습니다. 5,000개 기록이 곧 5,000개 후보라는 뜻도 아닙니다.

현재는 단일 추천의 규칙 후보 5,000개, 표시용 관련 증거 1,000기록/32MiB, JSON·HTML 16MiB 등의 제한이 있습니다. 입력 파일별 128MiB, 관련 기록 10,000개 제한도 있으므로 5,000기록을 넣었다는 사실만으로 단일 보고서 성공이 보장되지 않습니다. 제한 초과는 자료를 몰래 생략하거나 성공으로 표시하지 않고 실패합니다. 이 경우 비교에 필요한 계정·대조군·업무 흐름을 함께 유지하며 기능·호스트 등으로 입력 보고서를 나눠야 합니다. scope만 좁혀도 원본 파일은 먼저 읽으므로 파일 크기 제한은 별도입니다.
