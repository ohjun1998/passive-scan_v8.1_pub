# 2026-10-15 — PortSwigger 주제 기반 후보 추천 확대

## 사용자 요청

> IDOR·인가, XSS, SQLi, 민감정보, API KEY·TOKEN 외에 portswigger에서 확인 가능한 취약점 종류들도 반영해줘

이전 요청인 “일단은 후보를 추천하는 단계만 진행해보자”를 유지했다. 공식 분류를 조사하고 후보 추천 범위를 넓혔으며 자동 재현·키 인증·최종 취약점 확정은 추가하지 않았다. 이전 병합·진행 승인도 유지한다.

## 조사와 범위 결정

[PortSwigger Academy 공식 목록](https://portswigger.net/web-security/all-topics)을 확인해 취약점 관련 30주제를 33유형에 연결했다. Essential skills는 진단 방법이므로 유형 수에서 제외했다. 접근 제어를 IDOR·인가로 나누고 정보 노출을 민감정보·비밀값·상세 오류로 구분해 두 수가 다르다. CORS·CSRF·캐시·OAuth/JWT·XML·경쟁 상태와 다른 주제별 공식 설명도 확인했다.

Burp Scanner 개별 이슈 전체와 이번 프로젝트의 지원 규칙을 동일시하지 않았다. 공식 출처와 유형별 실제 구현 범위·추가 판단 사항을 목록으로 제공한다.

## 구현

- 유형 분류와 저장 단서 확장 모듈을 분리했다. SSRF·XXE·경로·명령어/템플릿/NoSQL 주입·역직렬화 오류·프로토타입 관련 입력·CORS·클릭재킹·인증·Host·캐시·업무 값 등을 다룬다.
- `evidence_signal`은 단서 후보, `review_surface`는 기능 점검 대상으로 구분한다. API·GraphQL·OAuth/JWT·LLM·업로드·DOM·경쟁 상태 등 기능 사용만으로 결함이라고 표시하지 않는다.
- 기본 AI는 단서만 최대 24개를 선택한다. `--ai-include-surfaces`는 같은 예산 안에서 기능 점검 대상을 추가한다. 기본 8개씩·동시 2개와 입력 크기·완료/ID 검증을 유지한다.
- HTML 기본 필터는 단서 후보다. 33개 유형의 단서/점검 대상/일치 단서 없음/추가 수집 필요 상태를 별도 표로 표시한다. 일치 단서 없음은 안전 판정이 아니다.
- 정규화 자료가 제거한 원시 프레이밍으로 요청 스머글링을 판단하지 않는다. JWT·쿠키 속성·multipart 파일 바이트·WebSocket 프레임·동시성과 캐시 재사용의 부족한 근거를 명시한다.
- 정상 대조 테스트에서 `Access-Control-Allow-Credentials` true까지 마스킹되던 문제를 찾았다. 이 정확한 헤더의 소문자 true/false만 보존하고 다른 값·자격정보는 계속 마스킹한다. 과거 마스킹 값은 복구하거나 true로 추측하지 않으며 자료 부족으로 표시한다. Fetch 표준의 대소문자 구분도 확인해 대문자 TRUE를 유효한 true로 바꾸지 않도록 대조했다.
- 버전·패키지 버전을 8.8.0으로 일치시켰다. 기존 batch 경로·과거 평가·httpx 20워커와 각 `-rl 10 -t 5`를 보존했다.

## 검증

- 새 기능 테스트 20개와 유형별 합성 표본 26개를 검증했다. 정상 CORS wildcard/동일 Origin, CSP/XFO와 Report-Only 구분, CSRF 표식, 명시적 XML 차단, 정상 파일 선택·URL 기능·업로드·GraphQL/JWT, 차단된 프로토타입 입력 등을 대조했다.
- 전체 314개 중 로컬 310개 통과·선택적 실제 환경 4개 제외. Python 컴파일·셸 문법·diff 공백 검사를 통과했다. 제외된 실제 Chromium·고정 httpx/Katana 검사는 별도 GitHub CI 대상이다.
- 혼합 합성 38기록에서 단서 25개·기능 점검 대상 11개를 분리했다. 기본 설정으로 단서 24개만 Codex CLI 0.162.1에 3회 호출해 약 66.057초에 검토했고 실패 0개였다. 단서 1개와 기능 대상 11개는 AI 미검토로 남았다.
- 별도 기능 표본 9기록/10항목은 명시적 옵션으로 2회 호출·약 34.810초에 검토했다. 단서 후보 수는 0으로 유지됐다. 두 실제 실행의 유형 합집합은 32개이며 요청 스머글링은 모델 미평가로 남겼다.
- 기존 77기록에서는 단서 후보 38개·API 기능 점검 대상 63개를 구분했고 규칙 처리 시간은 약 0.110초였다. 기능 발견 때문에 기본 AI 호출량을 늘리지 않는다. 항목 수는 취약점 수가 아니다.
- 합성 표본 결과는 운영 탐지 정확도·재현 결과가 아니다. 기존 인가 정답 50개를 새 유형의 정확도 근거로 사용하지 않았다. 모델 입력 생성 이후 유형 메타데이터·화면 표현은 정리했지만 모델 프롬프트·후보 판단 계약은 유지했다.
