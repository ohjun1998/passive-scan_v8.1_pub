이전 PR #5의 main 병합·배포 승인을 확인하고, AI 실행 정지 해결과 저장 요청·응답의 실제 모델 검증을 진행했다.

## 완료한 작업

- PR #5를 `911bd7355c916a884c0bb77e80944460b30fe66a`로 병합했다. main CI와 Source release가 성공했고 v8.6.0 태그·소스 ZIP·SHA256SUMS가 같은 커밋을 가리킴을 확인했다.
- 기존 ChatGPT 로그인과 설정을 유지하며 CLI 0.158.0·0.159.2·0.162.1, 프록시 전달, 세션 방식, 임시 위치, 상태 DB, 최대 120초 대기를 비교했다.
- 분석용 자식 CLI에서 프로젝트 문서 탐색을 생략하자 즉시 세션 시작 이벤트가 발생했다. 호출자의 저장소 지침과 관리 정책·읽기 전용 샌드박스는 유지했다. 내부 샌드박스 파일 조회의 정확한 정지 원인을 단정하지 않았다.
- `item.type=error`인 비치명적 경고를 도구 실행으로 오인하는 검사를 수정했다. 실제 도구 호출·최상위 실패는 계속 거부하며, 경고만으로 모델 응답이나 완료를 인정하지 않는다.
- 실제 doctor probe가 모델 응답·완료 검증을 통과했다. 기존 인증·사용자 설정은 수정하지 않았다.
- 첫 실제 리뷰에서 HTTP 400 `invalid_json_schema`와 미지원 `uniqueItems`를 확인했다. 전송 복사본만 조정하고 저장된 스키마·중복 ID·인용 검사를 유지했다.
- 훅·알림·셸 스냅숏·번들 스킬 설치를 분석 자식 프로세스에서 비활성화했다.
- 로컬 268개 테스트 중 264개 통과. GitHub CI `38713155909`에서 Python 3.10·3.12·3.13 검사와 별도 실제 Chromium 2개, httpx/Katana HTTP·HTTPS 2개 테스트까지 통과했다. 고정 도구 ZIP 체크섬도 확인했다.

- 11개 패킷 완료 후 12번째에서 세션 시작은 성공했지만 첫 모델 응답이 90초 제한을 넘었다. 완료 결과와 실패 이력을 보존하고, 첫 응답 대기를 180초로 늘려 실패 지점부터 명시적으로 재개했다. 배치 기본값에도 같은 값을 적용한다.

- 실제 분할 결과에서 잘못된 인용은 거부하고, 동일 검증 기준으로 명시적 재시도했다. 텍스트 첫 거부의 세부 원인은 원본 결과가 없어 단정하지 않았으며 JSON 발췌 불일치는 확인했다.
- 마지막 패킷에서는 모델이 패킷·의견에 없는 관찰 ID를 인용했다. 전송 스키마에 실제 ID enum을 추가하고 크기 한도를 지키도록 보강했다. 추가 인용 거부 뒤 의견·패킷 ID 연결과 발췌 형식을 프롬프트에 명시했고, 마지막 허용 재시도에서 정상 완료했다.

## 실제 저장 증거 검증

77개 관찰·36개 비교 패킷·50개 기존 라벨을 유지해 **36/36개 실제 모델 검토를 완료**했다. 82/82개 작업 조각이 검토됐으며 80/82개 조각·75/77개 기록에 인용 근거가 있다. 수동·미검증·미완료 패킷은 0개다. 전체 42회 시도 중 완료 36회, 과거 실패 6회이며 이력을 삭제하지 않았다.

집계 보고서와 기존 라벨 평가를 생성했다. TP 13·TN 35·FP 2·FN 0, 판단 보류·미검토 0이다. 정밀도 86.67%, 재현율 100%는 해당 50표본에만 적용된다. 정상 대조군 2개를 의심 의견에 함께 연결한 문제는 오탐으로 유지했다. 별도 개별 인용이 없어 두 기록은 ai_reviewed이고 evidence_validated가 아니다.

마지막 ID·프롬프트 보강을 포함한 로컬 273개 테스트 중 269개 통과·실제 환경 4개 제외를 확인했다. 승인된 35개 결과는 보존했고 마지막 패킷만 최종 보강 경로로 재시도했으므로, 전체를 최종 코드로 새로 실행한 성능 측정으로 표시하지 않는다. 대상에 새 요청을 보내지 않았으며 인증 정보와 원본 증거는 GitHub에 업로드하지 않는다.
