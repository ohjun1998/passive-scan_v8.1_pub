# v8.5.0 — 검토 실행·근거·산출물 고도화

현재 패치 버전은 [v8.5.1](V851.md)입니다. 실행 전 진단, 첫 응답 제한 지정, 집계 보고서의 실행 출처를 추가했습니다. 이 문서의 증거 패킷 형식과 기본 명령은 유지합니다.

[처음부터 끝까지의 시간순 흐름](FLOW_V85.md) · [최신 유스케이스](USE_CASES.md)

## 변경 내용

- 기능 라벨 또는 메소드·자원 경로로 증거를 묶고 패킷을 나눕니다. 기본 패킷은 지원 신원 증거를 포함해 12기록 / 65,536 bytes, 본문은 6,144 bytes입니다.
- 긴 JSON은 원본 RFC 6901 pointer별 값으로 나누고, 큰 문자열·JS/HTML은 UTF-8 경계를 유지해 나눕니다. 생략된 원본이나 불완전한 원본은 완전한 것으로 복원하지 않습니다.
- 사용자가 지정한 신원 응답·역할·객체 정책·출처를 연결합니다. 신원 응답의 실제 ID/역할 값이 일치해야 준비됩니다. 계정 생성·탐색·로그인은 하지 않습니다.
- v8.5 결과에는 구조화된 citations가 필요합니다. 실제 필드/텍스트 위치와 발췌를 검사하며 틀린 인용은 거부합니다. 의미·영향·취약점 여부까지 자동 검증한 것은 아닙니다.
- 불변 패킷·완료 결과를 다시 검증한 뒤 재개합니다. 실패한 묶음은 명시적인 --retry-failed로만 재실행하며 묶음당 최대 3회 시도로 제한합니다.
- 인증·기능 확인·MCP 설정·제출·응답·인용 검증의 상태와 안전한 오류 코드만 기록합니다. raw stderr·토큰·모델의 자유문을 진단 로그로 내보내지 않습니다.
- discovered/captured/partially_reviewed/ai_reviewed/evidence_validated 상태를 구분합니다. 재현 확인과 사람 finding 상태는 별도이며 자동으로 승격하지 않습니다.
- 독립적인 정답 라벨로 오탐·누락·판단 보류·precision/recall을 계산하고 PDF를 생성할 수 있습니다.

기존 v8.4 prepare/import/codex 경로는 호환용으로 유지합니다. 해당 구형 결과는 citation_validation=legacy_unverified이며 새 위치·발췌 검증을 거친 결과로 표시하지 않습니다.

## 1. 저장 증거 준비

```bash
python -m pip install -r requirements-v81.txt
python request_inventory.py import imports/capture.har --include-text --scope example.test --db reports/inventory.sqlite3
python request_inventory.py report --db reports/inventory.sqlite3 --output reports/base --xlsx
python ai_review.py batch-prepare --report reports/base --scope example.test --output reports/ai-batch --authority imports/authority.json
```

`--authority`는 선택 사항입니다. 제공하지 않은 신원·정책은 not_provided로 표시합니다. 보관한 본문이 없는 URL·JS 경로만으로 실제 응답이나 비밀값을 생성하지 않습니다. 일괄 처리 상한은 200패킷 / 패킷 JSON 합계 8 MiB이며 초과하면 새 묶음을 발행하지 않고 범위를 줄이도록 실패합니다. body-bytes 1,024~8,192, max-records 2~100, max-bytes 16,384~250,000 범위에서 지정할 수 있습니다.

`batch.json`은 원본 해시와 전체 작업/fragment 목록을 담은 불변 스냅샷입니다. 새 증거를 수집했으면 새 batch를 준비하세요. 기존 기본 보고서를 변경하지 않습니다.

## 2. 신원·접근 정책 형식

```json
{
  "identities": [
    {
      "actor": "alice",
      "observation_id": "로그인 또는 auth/me 응답의 실제 64자리 observation ID",
      "user_pointer": "/user/id",
      "role_pointer": "/user/role",
      "expected_user_id": 1,
      "expected_role": "USER",
      "provenance": "수집자가 확인한 auth/me 응답"
    }
  ],
  "policies": [
    {
      "observation_ids": ["검토할 요청의 실제 64자리 observation ID"],
      "owner": "bob",
      "allowed_actors": ["bob"],
      "expected_access": "deny",
      "provenance": "서비스 소유자가 제공한 주문 소유권 정책"
    }
  ]
}
```

신원 응답은 동일 scope의 관찰된 성공 JSON 응답이어야 하며 actor·기대 ID·역할과 일치해야 합니다. 필요한 신원 필드는 관련 패킷에도 포함합니다. capture_id 라벨이 같아도 같은 쿠키나 세션임을 독립적으로 보증하지 않습니다. session_continuity_verified는 false로 남기고 capture_link_status로 라벨 연결을 구분합니다.

접근 정책은 출처를 가진 사용자의 선언입니다. 서버 정책의 진실성이나 소유자의 실재성을 프로그램이 보증하지 않습니다. 해당 actor의 allowed_actors 포함 여부와 expected_access가 모순되면 준비를 거부합니다. 익명 정책은 actor 라벨을 anonymous처럼 명시해 연결하세요.

## 3. AI 검토 방식

### 현재 ChatGPT에서 검토 후 가져오기

각 `packets/<packet_id>/`의 `prompt.txt`와 `schema.json`을 제공해 결과 JSON을 받습니다. 패킷 내용은 신뢰할 수 없는 데이터로 취급하고, 새 요청·키 유효성 시험·로그인은 하지 않도록 지시합니다.

```bash
python ai_review.py batch-import --batch reports/ai-batch --packet-id 실제_패킷_ID --result imports/review.json
```

idempotent import는 동일한 결과만 허용합니다. 이미 가져온 결과와 내용이 다르면 덮어쓰지 않습니다. import는 모델 호출이나 구독 등급을 확인하는 기능이 아닙니다.

### Codex CLI 자동 경로

```bash
codex login
python ai_review.py batch-run --batch reports/ai-batch --timeout 300
python ai_review.py batch-run --batch reports/ai-batch --timeout 300 --retry-failed --max-attempts 3
```

완료 결과는 해시·스키마·패킷·인용을 다시 확인하고 건너뜁니다. 실패 이력이 있으면 기본 실행에서 재시도하지 않습니다. 새 실패가 발생하면 추가 모델 요청을 멈추며 이미 성공한 결과는 보존합니다. 인증·연결·요금/사용량 제한을 시간 제한 확대만으로 해결했다고 주장하지 않습니다.

첫 reasoning/agent_message 응답까지 최대 60초(또는 전체 제한이 더 짧으면 그 값), 전체 실행은 지정한 timeout을 적용합니다. 전체 프로세스 출력 상한은 2 MiB입니다. 도구 활동이 보이면 즉시 프로세스를 종료하고 결과를 거부합니다. 승인·호스트 보안 정책을 우회하지 않습니다. ChatGPT 로그인·도구/웹/MCP 비활성화·read-only·ephemeral 실행을 사용하며 API 키로 대체하지 않습니다. 표준 HTTP(S)/ALL_PROXY·NO_PROXY 환경은 모델 서비스 연결용으로 전달하되 진단 로그에 URL/자격정보를 기록하지 않습니다.

**Pro는 구독 이름이며 모델 ID가 아닙니다.** 선택적 --model에는 실제 CLI 모델 ID를 지정합니다. subscription_plan_verified는 false이며 자동 연결 성공이나 모델 검출 품질을 코드 변경만으로 보증하지 않습니다.

## 4. 실제 인용 형식

v8.5 review마다 기존 필드와 함께 다음 배열을 포함합니다. suspicious와 likely_benign은 최소 한 개의 검증 가능한 인용이 필요합니다. insufficient_evidence는 인용이 없을 수 있습니다.

```json
"citations": [
  {
    "observation_id": "해당 의견과 패킷에 포함된 실제 ID",
    "location": "response.body.json",
    "pointer": "/OWNER_ID",
    "excerpt": "2"
  }
]
```

위치 종류는 response.body.json / request.body.json / response.body.text / request.body.text / response.headers / request.headers / context / authority입니다. JSON·헤더 배열·context·authority는 RFC 6901 pointer와 실제 값 전체의 정확한 일치를 검사합니다. 문자열 값은 따옴표 없이, 숫자·불리언·배열·객체는 compact JSON으로 적습니다. 텍스트는 빈 pointer와 실제 연속 발췌를 사용합니다. json_fragment의 values는 원본 pointer를 키로 가지며 해당 키만 인용할 수 있습니다.

마스킹값을 인용하면 masked=true로 기록하며 실제 비밀값·유효성·권한을 확인한 것으로 해석하지 않습니다. 인용 검증은 AI가 내린 의미나 결론까지 확인하지 않습니다.

## 5. 상태·평가·PDF

```bash
python ai_review.py coverage --batch reports/ai-batch
python ai_review.py batch-report --batch reports/ai-batch --output reports/ai-report
python ai_review.py evaluate --review reports/ai-report --labels imports/labels.json --output reports/evaluation
python -m pip install -r requirements-report.txt
python ai_review.py pdf --review reports/ai-report --output reports/ai-report.pdf --font /path/to/KoreanFont.ttf
```

PDF는 Windows Malgun Gothic 또는 Linux NanumGothic 등 설치된 한국어 TTF를 사용합니다. 자동 탐색에 없으면 --font가 필요합니다. PDF 출력은 기존 파일을 덮어쓰지 않습니다. 기본 PDF는 최대 200개 의견을 보여 주고 생략 수를 표기합니다. 전체 JSON·HTML은 별도 보관합니다.

상태가 evidence_validated여도 이는 모든 해당 fragment에 검증한 인용이 연결됐다는 뜻입니다. 모든 필드의 안전성, 서비스 전체의 진단 완료, 재현 성공을 뜻하지 않습니다. 기본 보고서의 사람 finding 상태도 별도로 표시하고 reproduction_verified는 false로 유지합니다.

평가 라벨 형식:

```json
{
  "provenance": "AI 답변과 독립적으로 정의한 실습 정답",
  "cases": [
    {"case_id": "private-order", "observation_ids": ["실제 ID"], "expected_assessment": "suspicious", "category": "authorization"}
  ]
}
```

동일 정답 항목에 상충하는 의견이 있으면 prediction_conflict로 표시합니다. suspicious를 우선 집계하며 판단 보류/미검토는 별도 계산하고 양성 recall의 분모에는 포함합니다. 정답 라벨 범위에서만 유효한 값이며 일반적인 모델 정확도로 확대 해석하지 않습니다.

```bash
python examples/v85/demo.py --output reports/v85-demo
```

예제의 답변은 preset fixture이며 실제 AI 호출·탐지 품질 평가가 아닙니다. 기능·정답 평가 계산·PDF 연결을 오프라인으로 확인하는 예제입니다.

## 실패와 복구

`attempts/<packet_id>/history.json`에는 stage와 FIRST_RESPONSE_TIMEOUT / EXECUTION_TIMEOUT / CHATGPT_AUTH_REQUIRED / NETWORK_ERROR / RATE_LIMIT / OUTPUT_LIMIT / TOOL_ACTIVITY_BLOCKED / INVALID_COMPLETION_OR_RESULT 등 안전한 코드만 남깁니다. 실패 내용을 자유문으로 복사하지 않습니다. 결과 파일이나 프롬프트가 변경되면 재개를 거부합니다.

동일 batch에 대한 쓰기는 잠금 파일로 직렬화합니다. 비정상 종료로 `.review-write.lock`이 남으면 실제 작성 프로세스가 종료된 것을 확인한 뒤 해당 잠금 파일만 제거하고 재실행하세요. 자동으로 실행 중인 잠금을 삭제하지 않습니다.
