## 실제 요청 보호

httpx·Katana는 로컬 인증 프록시를 통해 요청합니다. 프록시는 각 요청과 HTTPS CONNECT 내부 요청에 대해 범위·메소드·고비용 경로·요청 수·수신 본문 예산을 확인합니다. 리다이렉트도 같은 경계를 거칩니다. 제한 소진은 SQLite에 저장되며 동시 예약은 트랜잭션으로 처리합니다.

Linux 실행에는 `openssl`이 필요합니다. 임시 CA와 설정은 제한된 임시 폴더에 만들고 해당 자식 프로세스만 신뢰하도록 전달합니다. OS의 전역 인증서를 변경하지 않습니다. 통제된 도구가 지원하는 프록시 옵션을 준수하는 것을 전제로 하며 OS 네트워크 격리 자체를 제공하지는 않습니다. 이 경로의 httpx·Katana는 `tools/probe-tools.json`의 버전과 SHA-256으로 고정하고 CI의 로컬 HTTP·HTTPS 서버에서 확인합니다.

**httpx 20개 워커, 각 `-rl 10 -t 5`는 유지합니다.** 기본 수집 모드와 명시적인 `--active` 조건도 유지합니다.

현재 RunGuard 기본 예산은 상태 DB당 실제 요청300회·수신 본문10MiB입니다. 입력 URL 한도와 실제 요청 예산은 다르며, 리다이렉트도 실제 요청에 포함합니다. 실행되지 않은 선택 URL은 `.deferred.txt`, 원인과 실제 전송 영수증은 `.network.json`에 남습니다. 프록시에서 생성한 오류는 대상 서버 응답으로 가져오지 않습니다.

게이트웨이에서 대상 서버로 연결할 때는 일반 인증서 검증을 유지합니다. 자체 서명 서버는 실행 환경에서 해당 CA를 신뢰하도록 설정해야 합니다. 자식 프로세스용 임시 CA가 대상 인증서 검증을 끄지는 않습니다. 전송 메타데이터는 `protected_gateway`로 표시하며 프록시 경로의 TLS·시간 정보를 대상과 직접 연결한 측정값으로 해석하지 않습니다.

GraphQL POST는 구문만으로 승인하지 않습니다. 승인 URL, JSON Content-Type, 허용된 GraphQL 본문 필드, 중복 키, 연산 종류·깊이·필드·곱셈 비용을 함께 확인합니다.

GraphQL 비용은 명시된 페이지 크기·구문을 이용한 보수적 추정입니다. 서버 스키마와 resolver 구현을 모르므로 실제 서버 비용 전체를 증명하지는 않습니다. `review_queue.py build/execute`에서도 같은 `--graphql-url` 승인이 필요합니다.

```bash
python safe_screenshots.py --active --urls reviewed_pages.txt --scope-file scope.txt --graphql-url https://example.test/graphql
```

이 예시는 사용자가 자신의 승인된 범위로 바꾸어 실행하는 능동 요청입니다. 승인 URL이 없으면 GraphQL 모양의 임의 POST도 자동으로 허용하지 않습니다.

## 캐시·보고서·연산 성능

- JS 캐시는 기존 JSONL을 한 번 가져온 뒤 `원래캐시경로.sqlite3`에서 해당 자산만 갱신합니다. 명시적 내보내기 때만 전체 스냅샷을 만듭니다. 이전 JSONL이 잘려 있었다면 불완전 상태를 유지하고 재분석합니다.
- OpenAPI 공유 참조를 중복 제거·재사용하고 문서 전체 작업량을 제한합니다. 제한에 걸리면 `schema`의 생략 정보를 남깁니다. 입력 크기·깊이만으로 작업량을 판단하지 않습니다.
- 512KiB 본문을 512조각으로 나누는 회귀 사례의 원문 해시는 512회에서 1회로 줄었습니다. 응답 파싱도 비교 쌍마다 반복하지 않고 관찰별로 재사용합니다.
- AI 실행 중 준비 배치를 한 번 검증하고 변경 감지와 개별 결과 검증을 유지하며 증분 집계합니다. 설정·인증·CLI가 바뀌면 실행 전 검사 캐시를 무효화합니다.
- JSON 산출물은 스트리밍으로 저장하고 HTML은 바이트·기록 수 예산에 따라 분할합니다. 분할 페이지는 일부 보기이며 전체 계정 비교와 흐름은 `analysis.json`에 보존합니다. Excel과 분석을 생성하는 과정은 여전히 전체 선택 기록을 메모리에 유지하므로 무제한 규모를 보장하지 않습니다.

## 반복 수집 순서와 자원 선택값

불변 관찰 변형과 `capture_events`를 분리했습니다. A→B→A는 관찰 2개와 이벤트 3개로 보존합니다. 기존 DB의 반복 횟수는 `migrated_summary` 한 건으로 이전하며 이미 잃어버린 과거 순서를 만들어내지 않습니다. 시간은 UTC로 정규화하고 수집 시간·가정한 시간대·해석 실패를 구분합니다.

자원을 선택하는 사용자 정의 헤더가 있다면 가져오기와 비교에서 지정할 수 있습니다. 자격정보 헤더는 이 옵션으로 등록할 수 없습니다.

```bash
python request_inventory.py import imports/session.har --scope example.test --resource-header X-Workspace
python request_inventory.py report --xlsx --resource-header X-Workspace
```

마스킹된 URL·본문·선택 헤더가 있으면 응답 차이는 보여주되 동일 자원이라고 확정하지 않습니다. actor 라벨은 여전히 사용자 선언이며 별도 신원·권한 근거가 필요합니다.

## 저장 증거 AI 검토

같은 저장 요청의 자원 선택값을 기준으로 소유자·다른 사용자·관리자·거부 응답 후보를 함께 배치합니다. 계정별 시나리오 이름이 달라도 같은 비교 묶음에 넣을 수 있습니다. 본문이 큰 계정 하나가 패킷을 독점하지 않도록 fragment를 교차 배치하고 필요한 신원 근거를 연결합니다.

`comparison_context`는 `complete_saved_group` 또는 `partial_saved_group`, 누락된 관찰 수, 자원 동일성의 불확실성을 표시합니다. 완전하다는 표시는 **저장된 비교 후보가 포함됐다는 뜻**이며 실제 서비스 전체 권한 검사가 끝났다는 뜻이 아닙니다.

개별 결과는 저장·읽기 크기 제한을 통일하고 전체 집계는 16MiB 예산을 적용합니다. 예산을 넘으면 결과를 확정하기 전에 실패하므로 기존 완료 결과와 재개 상태를 보존합니다. coverage와 결과 발행은 동일한 쓰기 잠금을 사용합니다.

기존 배치는 덮어쓰지 않습니다. 새 패킷 배치를 만들 때 패킷 ID가 달라질 수 있으므로 기존 22패킷의 결과와 섞지 마세요. 평가 라벨은 동일한 observation ID의 원본 증거에만 연결합니다.

```bash
python ai_review.py doctor --probe --timeout 45 --first-response-timeout 30 --output reports/doctor-v86
python ai_review.py batch-prepare --report reports/requests --scope example.test --authority imports/authority.json --output reports/ai-v86
python ai_review.py batch-run --batch reports/ai-v86 --timeout 300 --first-response-timeout 60
python ai_review.py coverage --batch reports/ai-v86
python ai_review.py batch-report --batch reports/ai-v86 --output reports/ai-v86-report
python ai_review.py evaluate --review reports/ai-v86-report --labels imports/labels.json --output reports/ai-v86-evaluation
```

doctor가 정상 완료된 환경에서 batch-run을 실행합니다. 실패 재시도는 `--retry-failed`로 명시하며 원인 없이 무제한 반복하지 않습니다. 수동 결과·합성 결과는 실제 모델 성공으로 표시하지 않습니다.

## 실제 실행 검증의 한계

현재 실행 환경은 ChatGPT 로그인·설정 검사와 CLI 모델 목록 조회를 통과했습니다. 모델 목록 캐시를 설치 버전과 맞춘 뒤에도 증거 없는 probe는 30초 동안 이벤트·stdout·stderr가 모두 0인 `CLI_EVENT_TIMEOUT`으로 끝났습니다. 근본 원인은 미확정이며 실제 모델 분석·50개 표본의 모델 정확도는 아직 측정하지 못했습니다.

ChatGPT 로그인 Codex CLI면 충분하며 별도 Pro 등급 확인을 추가하지 않습니다. [공식 인증 안내](https://learn.chatgpt.com/docs/auth)와 [비대화형 실행 안내](https://learn.chatgpt.com/docs/non-interactive-mode)를 확인했습니다. 실제 모델 결과가 없는 상태에서 오탐률·탐지율을 만들어내지 않습니다.
