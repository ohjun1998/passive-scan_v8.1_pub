# v8.9.0 — 저장 증거 중심 패시브 분석 고도화

[PR #9](https://github.com/ohjun1998/passive-scan_v8.1_pub/pull/9)의 main 병합, 최종 CI와 [v8.9.0 사전 배포](https://github.com/ohjun1998/passive-scan_v8.1_pub/releases/tag/v8.9.0)를 확인했습니다. 공개 소스 ZIP과 체크섬의 해시를 재현했고 기존 77건의 오프라인 추천·인용을 재검증했습니다. 추가 모델 전송 승인 대기와 실제 운영 평가 등 [현재 남은 단계](REMAINING_STEPS.md), [후속 검증 기록](V89_FOLLOWUP_VERIFICATION.json)을 확인하세요. 아래 합성 예제의 과거 실제 모델 검증과 이번 오프라인 검증은 별도 실행입니다.

이번 변경은 **이미 저장한 요청·응답의 후보 추천**을 개선합니다. `recommend`는 진단 대상의 URL·DNS에 새 요청을 보내지 않습니다. `--ai`는 선택한 마스킹 증거를 ChatGPT 로그인 Codex CLI의 모델 서버에 전달합니다. 기존 URL 수집·크롤링·httpx 실행은 별도이며 네트워크를 사용합니다.

## 달라진 기능

| 구분 | 동작 | 판단 한계 |
|---|---|---|
| 개선: 관련 증거 묶음 | 계정 대조·같은 기능의 입력 변형·응답 JSON 차이·저장 값 흐름을 후보에 연결 | 경로/객체 ID 값을 지워 합치지 않음. 관계는 추정이며 인과·정상성·신원 검증의 증명이 아님 |
| 신규: AI 결과 재사용 | 검증된 과거 결과를 동일 증거·범위·프롬프트·모델 설정·CLI/인증 설정에서 재사용 | 새 모델 실행과 구별. 기본 유효기간 24시간, 손상/만료/설정 변경 시 재검토 |
| 신규: 규칙 밖 탐색 | `--ai --discover`로 규칙 단서가 없는 저장 자료의 제한된 묶음만 검토 | 최대 3개 가설/묶음, medium/low만 허용. 빈 결과도 안전 판정이 아님 |
| 신규: 사람 판정 | 후속 점검 채택·기각·추가 맥락 필요를 기록하고 다음 추천에 반영 | 후보 ID와 전체 증거 해시 일치 필요. 자동 학습·최종 취약점 확정 아님 |
| 개선: 검토 화면 | 관련 기록의 표시용 JSON·원문 위치·응답 차이·새 실행/재사용·사람 판정 제공 | 마스킹 사본이며 큰 본문은 생략 바이트 수 표시 |
| 유지: 기존 범위 | PortSwigger Academy 30주제/33유형, 규칙 단서와 기능 점검 대상 구분, 기존 batch 명령 | 요청 스머글링 원시 전송 등 없는 자료는 미평가 |

## 실행

매번 새 출력 폴더를 사용합니다. 캐시와 사람 판정 파일은 원본 보고서·출력 보고서 밖에 둡니다.

```bash
# 규칙과 증거 묶음만 생성: 모델 호출 없음
python ai_review.py recommend --report reports/requests --scope example.test --output reports/recommend-01

# 규칙 후보 검토 + 규칙 밖 저장 자료 탐색 + 검증된 결과 재사용
python ai_review.py recommend --report reports/requests --scope example.test \
  --output reports/recommend-02 --ai --discover \
  --cache reports/candidate-ai-cache.sqlite3

# 같은 입력: 유효한 캐시는 재사용하고 아직 검토하지 않은 묶음을 진행
python ai_review.py recommend --report reports/requests --scope example.test \
  --output reports/recommend-03 --ai --discover \
  --cache reports/candidate-ai-cache.sqlite3
```

기본 새 검토 예산은 **24단위**입니다. 규칙 후보 1개와 탐색 묶음 1개가 각각 1단위를 사용하며, 탐색은 기본 최대 4단위를 공유합니다. 규칙 후보는 최대 8개씩, 전체 동시 실행은 2개입니다. `--ai-limit`, `--ai-batch-size`, `--ai-workers`, `--discovery-limit`으로 조절합니다. 캐시 적중은 새 예산을 소모하지 않으므로 다음 실행에서 미검토 자료로 진행할 수 있습니다. 한 번의 실행이 모든 기록을 LLM에 보냈다는 뜻은 아닙니다.

탐색 후보 풀은 저장 응답이 있는 비단서 기록에서 최대 200개의 대표 묶음을 구성합니다. 한 묶음은 최대 3개 관련 기록, 입력은 24KiB 이하입니다. 규칙 후보의 관련 근거는 최대 12개, 탐색 근거는 최대 24개입니다. 선택·실패·완료·재사용 상태와 생략 개수는 JSON에 남깁니다. 과대 입력은 축약을 숨기거나 성공으로 처리하지 않습니다. 기능 점검 대상의 기존 AI 검토는 `--ai-include-surfaces`로 따로 선택할 수 있습니다.

## 사람 판정

`index.html`에서 후보 ID를 복사합니다. 원본 추천 보고서의 manifest를 확인한 뒤 별도 파일에 판정을 추가합니다.

```bash
python ai_review.py feedback --review reports/recommend-02 \
  --candidate-id CANDIDATE_ID --decision follow_up \
  --note '업무 정책 담당자 확인이 필요한 후보' --output reports/candidate-feedback.json

python ai_review.py recommend --report reports/requests --scope example.test \
  --output reports/recommend-04 --ai --discover \
  --cache reports/candidate-ai-cache.sqlite3 --feedback reports/candidate-feedback.json
```

`follow_up`은 우선순위를 올립니다. `dismiss`는 규칙 후보의 새 AI 검토에서 제외하지만 후보와 원래 증거를 보존합니다. `needs_context`는 보류 맥락을 표시합니다. 탐색 가설도 캐시 결과에 사람 판정을 연결해 정렬·필터링합니다. 판정 이력은 덮어쓰지 않고 추가하며 동일 후보·동일 증거의 최신 판정을 적용합니다. 사람 메모를 모델 명령으로 넣지 않습니다. 자료가 달라지면 판정은 자동 승계되지 않습니다.

## 재사용과 실패 처리

CLI의 `--ai`는 출력 폴더 옆 `candidate-ai-cache.sqlite3`를 기본 사용합니다. `--no-cache`로 끄고 `--cache-max-age`로 1초~30일을 지정할 수 있습니다. Python API의 `cache_path=None`은 재사용을 끕니다.

재사용 키는 표시 발췌뿐 아니라 마스킹된 전체 저장 본문·헤더·권한 맥락·관련 증거 의존성·실제 프롬프트·범위·요청 모델·CLI와 인증/설정 파일 지문을 포함합니다. 원격 프록시 경로 설정은 유지하되 프로세스마다 바뀌는 프록시 사용자정보와 루프백 프록시의 임시 포트는 키에서 제외합니다. 이는 로컬 전송 핸들이며 모델 설정이 아닙니다. 실제 Codex 인증 파일과 통신 제한은 별도로 유지합니다. 설정의 원문 비밀값을 캐시 지문에 저장하지 않습니다.

캐시 결과는 원래 패킷·완료 영수증·도구 비활성화·의미 검증·프롬프트 해시를 다시 검사합니다. 이는 개인 로컬 캐시의 무결성 확인이며 외부 서명 증명은 아닙니다. 기본 모델 별칭의 서버 내부 버전 교체는 로컬에서 감지할 수 없으므로 유효기간과 **과거 결과 재사용** 표시를 유지합니다. 완전한 새 실행이 필요하면 `--no-cache`를 사용합니다.

검토 실패는 규칙 후보를 지우지 않고 실패 상태로 남깁니다. 새 AI 패킷 실패가 있으면 CLI는 종료 코드 3을 반환합니다. 캐시 쓰기 실패는 이미 검증한 새 결과를 무효화하지 않습니다. 캐시는 최대 2,000항목/128MiB, 파일 권한 600으로 제한하며 원본 자료와 마찬가지로 별도 관리해야 합니다.

## 산출물과 검증

`index.html`, `recommendations.json`, 새 실행의 `model-inputs/`·`model-results/`, 관련 기록의 `evidence-records/`를 생성합니다. 재사용만 한 실행에는 새 모델 입력 파일을 만들지 않습니다. 증거 화면은 본문별 16KiB 사본과 생략 바이트 수를 제공하며 최대 1,000기록/32MiB로 제한합니다. 전체 저장 증거의 해시는 표시 제한과 무관합니다.

```bash
# example.test에 접속하지 않는 합성 데모
python examples/v89/demo.py --output reports/v89-demo

# 기존 ChatGPT 로그인 모델을 이용하는 선택적 데모
python examples/v89/demo.py --output reports/v89-demo-ai --ai
```
