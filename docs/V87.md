# v8.7.0 — 저장 증거의 취약점 후보 추천

목표는 URL에 매핑된 요청·응답에서 후속 진단 가치가 있는 후보와 근거를 보여 주는 것입니다. 모든 기록마다 긴 검토 보고서를 생성하던 경로에 더해, **전체 저장 자료의 규칙 검사 → 선택 후보의 짧은 AI 판단 → 사람이 볼 후보 목록**을 제공합니다. 기존 `batch-*` 명령은 보존합니다.

## 실행

먼저 HAR·Burp XML·브라우저 기록 등으로 `request_inventory.py` 보고서를 만듭니다. URL 목록만 있으면 본문이 필요한 규칙은 적용할 수 없습니다. 기존 마스킹으로 제거된 비밀값을 복원하지 않습니다.

```bash
# 규칙 후보 추천만 실행: 대상 요청과 모델 호출 없음
python ai_review.py recommend --report reports/requests \
  --scope example.test --output reports/candidates

# ChatGPT 로그인 Codex CLI로 우선 후보만 선택 검토
python ai_review.py recommend --report reports/requests \
  --scope example.test --output reports/candidates-ai --ai \
  --ai-limit 24 --ai-batch-size 8 --ai-workers 2

# 계정·정책 자료가 있으면 선택적으로 연결
python ai_review.py recommend --report reports/requests \
  --scope example.test --authority authority.json \
  --output reports/candidates-policy --ai

# 합성 예제: 모델 호출이나 대상 접속 없음
python examples/v87/demo.py --output reports/v87-demo
```

출력 폴더는 새 경로를 지정합니다. `index.html`에서 유형·상태·검색어로 후보를 필터링하고, `recommendations.json`에서 전체 상태·커버리지·실행 영수증을 확인합니다. AI에 보낸 마스킹된 후보 패킷은 `model-inputs/`에 보존하며 manifest로 출력 무결성을 확인합니다.

| 유형 | 저장 자료에서 찾는 단서 | 판단의 한계 |
|---|---|---|
| IDOR | 식별자와 응답 소유자 필드, 차단 기대 요청의 2xx 응답 | 현재 계정·소유권·공유 정책이 없으면 낮은 강도 후보 |
| 인가·권한 | 선언된 차단 정책과 본문 있는 성공 응답 | 로그인 페이지·일반 성공 응답과 실제 제한 데이터 구분 필요 |
| XSS | 입력의 HTML·태그·스크립트 문맥 반영, JS source/sink 동시 등장 | 브라우저 실행·우회 미검증. source/sink는 데이터 흐름 추적 아님 |
| SQLi | SQLSTATE 등 구체적인 DB 오류 패턴 | 오류 문자열만으로 SQLi 확정 불가. Blind SQLi 비탐지 가능 |
| 민감정보 | 응답의 개인정보·비밀번호 해시 등 필드 | 본인에게 필요한 정보·공개 자료일 수 있음 |
| API KEY·TOKEN·비밀값 | URL 자격정보 필드, 응답 비밀 필드·키 형식·클라이언트 설정 | 공개 키·예제·정상 발급과 구분 필요. 마스킹 값 유효성 알 수 없음 |

일반 요청의 Authorization/Cookie 자체는 노출 후보로 만들지 않습니다. 일반 로그인·OAuth 경로의 access/refresh token 발급 필드는 비밀값 후보 규칙에서 제외합니다. 평문 HTML 텍스트·이스케이프된 HTML·JSON의 단순 반영은 반사 XSS 규칙에서 제외합니다. 규칙은 지원 패턴을 찾으며 모든 XSS·SQLi·비밀 형식을 탐지하지는 않습니다.

## AI 예산과 결과 해석

AI 없이도 모든 범위 내 기록에 지원 규칙을 적용합니다. `--ai`가 있을 때만 기본 최대 24개 후보를 선택합니다. 각 유형에 첫 기회를 배정한 뒤 우선순위 순으로 채워 인가 후보가 다른 유형을 모두 밀어내지 않게 합니다. 상한이 유형 수보다 작으면 일부 유형은 선택되지 않을 수 있습니다.

후보 최대 8개씩, 압축 JSON 24KiB 이하로 묶고 기본 2개 호출을 동시에 실행합니다. 선택 상한은 1~100, 묶음 크기는 1~12, 동시 실행은 1~4로 제한합니다. 큰 맥락 때문에 단일 후보도 예산을 넘으면 `oversized_candidate_ids`에 남기고 수동 검토 대상으로 유지합니다. 전체 모델 제한은 기본 300초, 첫 응답 제한은 180초이며 `--model`을 선택할 수 있습니다.

모델은 후보 ID마다 `retain`·`dismiss`·`needs_context`, 검토 순서, 짧은 이유, 다음 확인만 반환합니다. 유형·판단 대상·대조군·근거 위치를 모델이 바꾸지 못하게 하고, 새 후보 생성·보고서 초안·재현 작업은 요청하지 않습니다. 지원 규칙에 걸리지 않은 기록을 AI가 별도로 읽지는 않습니다.

| 표시 | 의미 |
|---|---|
| 규칙 후보 | AI 미선택·미실행·실패·크기 초과를 포함한 로컬 단서 |
| AI 후속 검토 추천 | 제공된 단서가 후속 진단 가치가 있다는 의견 |
| AI 단서 기각 | 해당 단서가 충분하지 않다는 의견. 서비스 안전 판정 아님 |
| 추가 맥락 필요 | 신원·정책·입력 제어·공개 범위 등 부족한 정보가 있음 |
| high/medium/low | 검토 순서. 취약점 확정 확률이나 심각도 아님 |

모든 후보의 `confirmed`와 `reproduction_verified`는 false입니다. `evidence_location_verified`는 마스킹된 로컬 증거에서 위치·발췌가 일치한다는 뜻입니다. 의미나 취약점의 검증을 뜻하지 않습니다. `subject_ids`는 판단 대상이고 `support_ids`는 정상 비교 자료이며 서로 분리합니다.

`rule_processed_records`는 규칙 처리한 기록 수, `ai_reviewed_candidates`는 실제 AI 결과를 검증한 후보 수입니다. 둘은 단위와 범위가 다릅니다. 한 기록에 여러 후보가 생길 수 있으며 비교 자료를 AI가 읽어도 그 기록을 의심 대상으로 집계하지 않습니다. 후보가 없거나 AI가 미검토한 기록을 안전하다고 표시하지 않습니다. 일부 AI 호출 실패 시 후보·실패 상태를 발행하고 종료 코드 3을 반환합니다. 기본 성공은 0, 입력·발행 실패는 2입니다.

## 검증과 보존

[검증 요약](V87_VERIFICATION.json)에 혼합 합성 표본과 기존 77기록 측정을 분리했습니다. 혼합 표본은 정상 대조·이스케이프·JSON 반영·정상 OAuth 발급을 포함합니다. 기존 50개 정답 라벨은 모두 인가 유형이므로 XSS·SQLi·비밀값 정확도를 증명하지 않습니다. 기존 v8.6.1의 대조군 연결 오탐 2건과 과거 결과를 덮어쓰지 않습니다.

이 명령은 저장 파일과 선택한 모델만 사용하며 대상 추가 요청·키 인증·자동 재현은 0건입니다. httpx 수집 설정 **20워커, 각 `-rl 10 -t 5`**는 유지합니다. [전체 유스케이스](USE_CASES.md) · [현재 범위·후속 단계](REMAINING_STEPS.md).
