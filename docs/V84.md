# v8.4.1 — 저장 증거 AI 검토 실행 기능

현재 GitHub v8.2 소스에 AI 검토 실행 경로와 정보 노출 검토 프롬프트를 통합했습니다. 이전 v8.4 개발본 전체의 복구본은 아닙니다. 기존 v8.2 수집·분석·선택 조회 기능을 유지하며, 아래 AI 기능을 추가했습니다.

[전체 시간순 흐름도·도구와 데이터](FLOW_V84.md) · [유스케이스](USE_CASES.md) · [GitHub 작업 과정](GITHUB_PROCESS.md)

## 실행 순서

Python 3.10 이상. 아래 예제는 가상의 저장 파일만 처리하며 대상 접속이 없습니다.

```bash
python -m pip install -r requirements-v81.txt
python request_inventory.py import examples/demo.har examples/v82-demo.jsonl examples/v84-disclosure-demo.jsonl --scope example.test --db reports/demo.sqlite3
python request_inventory.py report --db reports/demo.sqlite3 --output reports/base-v841 --xlsx
python ai_review.py prepare --report reports/base-v841 --scope example.test --output reports/ai-input-v841
```

`ai-input-v841/prompt.txt`에는 공통 지시와 증거 JSON이 함께 들어 있습니다. `schema.json`은 요구하는 반환 형식입니다. 전달 전에 마스킹 상태를 직접 확인하고, 사용 중인 ChatGPT에 두 파일을 제공해 스키마에 맞는 JSON 결과를 저장합니다. 원본 HAR·세션 쿠키·토큰은 제공하지 않습니다.

```bash
python ai_review.py import --packet reports/ai-input-v841/packet.json --result imports/ai-result.json --output reports/ai-result-v841
```

`import`는 모델을 호출하지 않습니다. 입력 JSON의 형식·packet ID·허용된 증거 ID를 검사합니다. 성공하면 `index.html`, `review.md`, `ai_review.json`, `packet.json`, `execution.json`, `manifest.json`을 별도 폴더에 생성합니다. 모델 실행 확인은 false로 표시하며 검토한 내용의 정확성까지 검증한 것으로 간주하지 않습니다.

## 선택 경로: 로컬 Codex CLI

설치된 공식 Codex CLI에서 먼저 `codex login`으로 ChatGPT 계정에 로그인합니다. 실행 코드는 로그인 파일을 직접 읽거나 API 키를 사용하지 않습니다.

```bash
codex login
python ai_review.py codex --report reports/base-v841 --scope example.test --output reports/ai-codex-v841 --timeout 600
```

필요하면 `--model`에 사용 가능한 Codex 모델 ID를 지정합니다. **Pro는 구독 이름이며 모델 ID가 아닙니다.** `--model pro`는 거부합니다. 구독 등급과 실제 사용할 수 있는 모델·사용량은 코드에서 검증하지 않습니다.

CLI 로그인 상태·기능 목록·MCP 설정을 먼저 확인합니다. 도구 기능과 웹 검색, 구성된 MCP 서버를 끄고 별도 임시 디렉터리에서 read-only·ephemeral 모드로 실행합니다. 시간 초과, 프로세스 출력 2 MiB 초과, 도구 활동 이벤트, 오류·알 수 없는 이벤트, 완료 이벤트 누락, 잘못된 JSON을 발견하면 결과를 반영하지 않습니다. 이 단계는 모델 서비스에 증거를 전송합니다. 대상 API를 진단하는 HTTP 클라이언트는 사용하지 않습니다.

현재 개발 환경에는 Codex CLI가 없습니다. 모의 CLI 연결 테스트는 통과했지만 실제 CLI 모델 호출과 Pro 구독 등급을 검증한 결과는 아닙니다. CLI 버전·호스트 정책 때문에 기능을 끌 수 없거나 인식하지 못하는 이벤트가 나오면 실패로 종료합니다. `prepare` → ChatGPT 검토 → `import` 경로를 사용할 수 있습니다.

## 검토 범위와 판정

| 검토 대상 | 판단 근거 | 단정하지 않는 사항 |
|---|---|---|
| API 민감정보 과다 노출 | 응답 필드·호출자·소유권·기대 권한·반환 필요성 | UI 미표시만으로 권한 위반 확정 |
| JS/HTML 비밀정보 노출 | 실제 수집 본문·주석·설정·위치·마스킹한 발췌 | URL만으로 파일 내용 추정, 키 유효성 추정 |
| 오류 내부정보 노출 | 스택·SQL·DB 구조·경로·내부 호스트·디버그 정보 | DB 오류로 SQLi, 스택으로 RCE 확정 |
| 기존 계정 비교 | 동일 URL·메소드·body의 저장 응답과 라벨 | 200·응답 유사성만으로 IDOR 확정 |

계정은 수집자가 붙인 `context.actor` 라벨입니다. AI가 계정을 검색하거나 로그인하지 않습니다. 실제 신원·역할·객체 소유권·서비스 정책은 사람이 확보한 증거로 확인해야 합니다.

세 분류는 `suspicious`, `likely_benign`, `insufficient_evidence`입니다. 취약점 확정·실제 재현·최종 제출 승인은 사람이 수행합니다. AI의 `report_draft.steps`는 저장된 관찰이나 계획이며 새 요청 실행 증명이 아닙니다.

## 증거·예산·실패 처리

- 기본 패킷 100개 기록 / 500,000 bytes. 최대 1,000개 / 2 MiB. 각 본문은 8 KiB까지이며 잘림·생략을 표시합니다. 실제 관찰·기존 후보 점수 순으로 선택하며 모든 후보가 포함되는 것은 아닙니다.
- scope에 포함된 기록만 선택합니다. 계정 비교는 두 증거가 모두 선택됐을 때만 전달합니다. URL 정적 발견은 실제 요청·응답 확보와 구분합니다.
- 자격정보는 다시 마스킹합니다. 이미 지워진 값은 복원하지 않습니다. 자유 텍스트·개인정보의 마스킹은 완전하지 않으므로 제공 전 검토가 필요합니다.
- 기본 보고서의 요청 JSONL·분석 JSON 해시와 run ID를 검증합니다. 기존 v8.2 보고서는 manifest가 없어도 사용할 수 있으나 원본 manifest 미검증으로 표시됩니다. 해시는 내용 일치를 확인하며 원본의 진실성이나 전자서명을 보장하지 않습니다.
- `prepare`와 결과 출력은 새 폴더에만 저장합니다. 기존 기본 보고서·검토 상태는 변경하지 않습니다. packet/result 불일치나 실패 시 해당 결과를 다시 확인하고 새 출력 폴더로 재시도합니다.
- 별도 AI 보고서는 선택 증거 수·검토 의견에 연결된 증거 수·미검토 수를 표시합니다. 의견이 없는 기록은 정상으로 판정한 기록이 아닙니다.

이 버전에는 이전 개발본의 case/test-run 모듈 복구, 자동 계정 발급, 대상에 대한 AI 재현 요청, 자동 취약점 확정 기능이 포함되지 않습니다.
